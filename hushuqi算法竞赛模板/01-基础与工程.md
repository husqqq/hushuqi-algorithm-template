# 1. 基础与工程

> 本章解决“代码如何可靠地开始、读写、调试和提交”。默认 C++20、0 下标、左闭右开区间 `[l,r)`；使用 `#define int long long` 时，比赛入口常写成 `signed main()`。每个代码型知识点都在正文给出完整实现，可直接复制。

## 1.1 基础代码框架

### 1.1.001 C++ 通用头文件与类型别名

统一头文件、整数宽度、无穷大与浮点容差是全书其余代码的公共前导，后续章节不再重复。`#define int long long` 必须写在系统头之后；若先于 `<bits/stdc++.h>` 展开，标准库中的 `int` 也会被替换，代码无法编译。宏展开后 `INF` 的类型和值分别是 `long long` 与 `numeric_limits<long long>::max()/4`。它只适合在已经证明数值范围受控时作哨兵；可能接近完整整数范围的算法必须把“不可达”与数值分开表示。

```cpp
#include <bits/stdc++.h>

using namespace std;

#define int long long

constexpr long long INF = numeric_limits<long long>::max() / 4;
constexpr long double EPS = 1E-12L;
```

一般整数按题目范围使用 `int`；外部二进制格式或系统接口要求固定位宽时使用 `int`、`unsigned long long` 等明确类型。乘积可能超 $9\times10^{18}$ 时在运算前转成 `__int128`，见 [1.2.002 `__int128` 输入输出](#12002)。

### 1.1.002 标准 `main` / 多测框架

`signed main()` 是规避 `int` 宏的常用写法，因为单独的 `signed` 等价于未被宏替换的 `signed int`。它不是唯一写法；也可以不用该宏，或在入口前 `#undef int` 后使用标准的 `int main()`。单测逻辑放进 `solve()`，多测只在 `main` 中循环调用，便于对拍时复用同一份 `solve()`。

```cpp
void solve()
{
    // 处理一组数据，n 为本组规模
    int n;
    cin >> n;
}

signed main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t = 1;
    cin >> t;         // 单测题删除本行，保留 t = 1
    while (t--)
    {
        solve();
    }
}
```

交互题不要解绑 `cin`/`cout`，且每次询问后 `cout << flush`，否则输出滞留缓冲区会导致死等。框架额外开销 $O(t)$，总复杂度为各组 `solve()` 之和。

### 1.1.003 常量、无穷大、浮点误差与符号函数

不能用浮点字面量表达要求精确的整数，例如 `1000000000000000001LL` 转成 `double` 后会舍入；纯整数常量应写整数后缀。`sgn` 只处理“按给定绝对容差与零比较”，返回 $-1$、$0$ 或 $1$。

```cpp
int sgn(long double x, long double eps = EPS)
{
    // 返回 x 相对 0 的符号：-1、0 或 1
    return (x > eps) - (x < -eps);
}
```

用法如 `if (sgn(cross, eps) == 0)` 判共线。`eps` 必须按数据尺度和量纲选择；比较两个一般浮点数时还要考虑相对误差或 ULP，不能把固定绝对 `EPS` 当成通用判据。整数几何优先使用精确叉积。

### 1.1.004 常用函数重载与容器输出

`chmin/chmax` 把“比较、赋值、返回是否更新”三步并成一次调用，返回值还能顺带记录转移来源（如最短路的前驱）。`vector` 的流重载只为本地对拍省样板，正式提交若与他人代码合并需留意命名冲突。

```cpp
template <class T> bool chmin(T &x, const T &y)
{
    // y < x 时把 x 降到 y 并返回 true
    if (y < x)
    {
        x = y;
        return true;
    }
    return false;
}

template <class T> bool chmax(T &x, const T &y)
{
    // x < y 时把 x 升到 y 并返回 true
    if (x < y)
    {
        x = y;
        return true;
    }
    return false;
}

template <class T> istream &operator>>(istream &in, vector<T> &a)
{
    // 按 a 的既有长度依次读入
    for (auto &x : a)
    {
        in >> x;
    }
    return in;
}

template <class T> ostream &operator<<(ostream &out, const vector<T> &a)
{
    // 空格分隔输出，不带行尾空格
    for (int i = 0; i < (int)a.size(); i++)
    {
        if (i)
        {
            out << ' ';
        }
        out << a[i];
    }
    return out;
}
```

`vector<int> a(n); cin >> a;` 依赖预设长度，重载不改变容器大小。`chmin/chmax` 要求两个实参类型相同，避免混合有符号比较或隐式窄化；需要转换时由调用处显式完成。更新为 $O(1)$，容器读写为 $O(n)$。

### 1.1.005 Lambda 递归写法

只服务单个算法的 DFS 留在函数内部，避免全局状态与冗长函数名。C++ 里 lambda 无法直接引用自身，用 `auto &&self` 显式传入（Y 组合子写法）；有返回值时必须写出 `-> T`，否则编译器推不出递归返回类型。

```cpp
auto dfs = [&](auto &&self, int x, int fa) -> void
{
    // self 传自身用于递归，fa 为父结点，dep 记录深度
    for (auto y : g[x])
    {
        if (y == fa)
        {
            continue;
        }
        dep[y] = dep[x] + 1;
        self(self, y, x);
    }
};
dfs(dfs, 0, -1);
```

递归深度可能达 $O(n)$（链状图）时须确认系统栈足够，必要时参见 [1.2.007 手动扩大栈空间](#12007)；本模板仍直接使用递归函数或递归 lambda，不用容器模拟调用帧。复杂度与普通递归一致，每层仅多传一个引用。

### 1.1.006 C 语言基础模板与常用 C 库

仅用于强制 C、嵌入式接口或评测明确要求 `.c` 的场景，不与本模板的 C++ 宏混用。$64$ 位整数的读写用 `<inttypes.h>` 的 `SCNd64`/`PRId64` 宏，跨平台格式串才正确。

```c
#include <assert.h>
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    int64_t n;
    if (scanf("%" SCNd64, &n) != 1)
    {
        return 0;
    }
    printf("%" PRId64 "\n", n);
    return 0;
}
```

`malloc/calloc` 后必须 `free`；`memset` 等库函数复杂度取决于参数（$O(n)$），框架本身 $O(1)$。

### 1.1.007 Python 基础模板

适合大整数、字符串处理和对拍暴力。`input = sys.stdin.buffer.readline` 绕开 Python 慢速行读取；正式解题前先估常数与递归深度，Python 递归默认上限约 $1000$ 层。

```python
import sys

input = sys.stdin.buffer.readline

def solve() -> None:
    n = int(input())
    a = list(map(int, input().split()))
    print(sum(a[:n]))

def main() -> None:
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```

未知组数时遍历 `sys.stdin.buffer`；深递归优先改迭代，确需时再 `sys.setrecursionlimit`（并注意实际系统栈限制）。

## 1.2 输入输出

### 1.2.001 快速输入输出

普通题关闭同步的 `cin/cout` 已足够；输入达数百万整数且 I/O 成瓶颈时才用 `FastInput`。核心是一次 `fread` 灌满 $64$ KiB 缓冲、逐字节手动解析，省掉 `cin` 的格式化开销。读整数时先跳空白、再处理可选负号、逐位累加；EOF、格式错误或目标类型越界时返回 `false`。构造时可传入 `FILE *` 作为读取流，比赛中保持默认的 `stdin`，本地测试可传临时流而不依赖外部标准输入。

```cpp
struct FastInput
{
    static constexpr int S = 1 << 16; // 缓冲区容量（字节）
    array<char, S> buf{};             // fread 批量读入的原始字节
    FILE *src = stdin;                // 当前读取的 C 输入流
    int p = 0;                        // 下一个未读位置
    int n = 0;                        // 当前有效字节数

    // 参数 src 为读取来源，默认从标准输入读取。
    FastInput(FILE *src = stdin) : src(src) {}

    char get()
    {
        // 返回下一个输入字节，EOF 返回 0
        if (p == n)
        {
            n = fread(buf.data(), 1, S, src);
            p = 0;
            if (!n)
            {
                return 0;
            }
        }
        return buf[p++];
    }

    template <class T> bool read(T &x)
    {
        // 读一个 T 范围内的整数，成功返回 true
        static_assert(is_integral_v<T> && !is_same_v<remove_cv_t<T>, bool>);
        using U = make_unsigned_t<T>;
        auto c = get();
        while (c && c <= ' ')
        {
            c = get();
        }
        if (!c)
        {
            return false;
        }
        bool neg = c == '-';
        if (neg)
        {
            c = get();
        }
        if (c < '0' || c > '9')
        {
            return false;
        }
        U lim = numeric_limits<U>::max();
        if constexpr (is_signed_v<T>)
        {
            lim = (U)numeric_limits<T>::max() + (neg ? 1 : 0);
        }
        bool fit = true;
        U v = 0;
        while ('0' <= c && c <= '9')
        {
            U d = (U)(c - '0');
            if (fit && v > (lim - d) / 10)
            {
                fit = false;
            }
            if (fit)
            {
                v = v * 10 + d;
            }
            c = get();
        }
        if (!fit)
        {
            return false;
        }
        if constexpr (is_unsigned_v<T>)
        {
            if (neg)
            {
                return false;
            }
            x = (T)v;
        }
        else if (neg)
        {
            U absMin = (U)numeric_limits<T>::max() + 1;
            if (v == absMin)
            {
                x = numeric_limits<T>::min();
            }
            else
            {
                x = -((T)v);
            }
        }
        else
        {
            x = (T)v;
        }
        return true;
    }

    bool read(string &s)
    {
        // 读一个非空白字符串（以空白或 EOF 结束）
        auto c = get();
        while (c && c <= ' ')
        {
            c = get();
        }
        if (!c)
        {
            return false;
        }
        s.clear();
        while (c > ' ')
        {
            s.push_back(c);
            c = get();
        }
        return true;
    }
};
```

`FastInput in; in.read(n);` 直接取代 `cin >> n`。整数目标可以是有符号或无符号整型；负号不能写入无符号目标，超出 `T` 范围时返回 `false`。同一程序内不要混用 `FastInput`、`cin` 与 `scanf`，它们各自维护缓冲。读长度 $L$ 的输入为 $O(L)$，缓冲固定为 $O(2^{16})$。

### 1.2.002 `__int128` 输入输出

`__int128` 没有流重载，读写需要经字符串中转。`toString` 用无符号幅值逐位取模，避开 $-2^{127}$ 取负溢出；`parseInt128` 严格检查符号、数字和范围，失败时返回空值。计算 `a*b%mod` 时写 `(__int128)a*b%mod`，让乘法在 $128$ 位中完成。

```cpp
string toString(__int128 x)
{
    // 128 位整数转十进制字符串
    if (!x)
    {
        return "0";
    }
    auto neg = x < 0;
    auto y = neg ? 0 - (unsigned __int128)x : (unsigned __int128)x;
    string s;
    while (y)
    {
        s.push_back(char('0' + y % 10));
        y /= 10;
    }
    if (neg)
    {
        s.push_back('-');
    }
    reverse(s.begin(), s.end());
    return s;
}

optional<__int128> parseInt128(const string &s)
{
    // 严格解析十进制串，非法或越界时返回空
    if (s.empty())
    {
        return nullopt;
    }
    bool neg = s[0] == '-';
    int p = neg || s[0] == '+';
    if (p == (int)s.size())
    {
        return nullopt;
    }
    unsigned __int128 lim = (unsigned __int128)1 << 127;
    if (!neg)
    {
        lim--;
    }
    unsigned __int128 x = 0;
    for (; p < (int)s.size(); p++)
    {
        if (s[p] < '0' || s[p] > '9')
        {
            return nullopt;
        }
        unsigned d = (unsigned)(s[p] - '0');
        if (x > (lim - d) / 10)
        {
            return nullopt;
        }
        x = x * 10 + d;
    }
    if (!neg)
    {
        return (__int128)x;
    }
    if (x == ((unsigned __int128)1 << 127))
    {
        return -(__int128)(x - 1) - 1;
    }
    return -(__int128)x;
}
```

解析与输出均为 $O(d)$，其中 $d$ 是十进制位数。下面用最小值往返、带正号输入和一次乘法快速检查主路径，并保留一条非法字符检查：

```cpp
signed main()
{
    string s = "-170141183460469231731687303715884105728";
    auto x = parseInt128(s);
    assert(x && toString(*x) == s);
    assert(parseInt128("+42") == optional<__int128>(42));
    assert(!parseInt128("12x"));
    auto a = parseInt128("123456789");
    auto b = parseInt128("987654321");
    assert(a && b && toString(*a * *b) == "121932631112635269");
}
```

### 1.2.003 泛型读写封装

容器长度已知时，[1.1.004 常用函数重载与容器输出](#11004) 已提供 `vector` 流重载。本条只展示调用，不重复定义同一组函数；复制模板时保留 1.1.004 的唯一实现即可。

```cpp
vector<int> a(n);
cin >> a;
cout << a << '\n';
```

必须先 `vector<int> a(n)` 定好长度再 `cin >> a`——重载按既有 `size()` 读取，不会自动扩容。长度 $n$ 时 $O(n)$ 时间、$O(1)$ 额外空间。

### 1.2.004 浮点数与输出精度控制

`fixed` 下 `setprecision(k)` 是小数位数，`defaultfloat` 下是有效数字，二者含义不同，误用会少输出几位导致精度不足。判题给绝对/相对误差时，多输出 $2$ 到 $4$ 位保险。

```cpp
cout << fixed << setprecision(12) << x << '\n';
cout << scientific << setprecision(6) << x << '\n';
cout << defaultfloat;   // 恢复默认模式
```

单次格式化与位数线性相关，竞赛中视为 $O(1)$。

### 1.2.005 未知长度的一行输入

一行元素个数未知但行边界有语义时，不能用 `while (cin >> x)`——它跨行读取会吞掉下一行数据。正确做法是整行 `getline` 后用 `stringstream` 切分。

```cpp
string line;
getline(cin >> ws, line);
stringstream ss(line);
vector<int> a;
for (int x; ss >> x;)
{
    a.push_back(x);
}
```

`cin >> ws` 跳过前导空白（含上一行残留换行）。若空行本身有效，则不能吃空白，应先单独消费前一个换行再 `getline(cin, line)`。行长 $L$ 时 $O(L)$。

### 1.2.006 文件输入输出

本地固定样例、传统文件题与对拍时重定向标准流。用 `#ifndef ONLINE_JUDGE` 包裹，保证提交到评测机时不生效——否则普通标准输入题会因重定向读不到数据。

```cpp
#ifndef ONLINE_JUDGE
freopen("input.txt", "r", stdin);
freopen("output.txt", "w", stdout);
#endif
```

若题面要求固定文件名（如 `data.in`），按题面改。只改变流来源，算法复杂度不变。

### 1.2.007 手动扩大栈空间

仅在递归写法已经清楚、且确认栈溢出时使用。C++ 的 DFS、分治和回溯仍直接写普通递归函数或递归 lambda；$256$ MiB 栈不等于可安全递归任意层——栈帧里的大对象、局部容器仍会吃掉配额。

Linux 运行前抬高软限制：

```bash
ulimit -s 262144
./main
```

Windows MinGW 在链接期设定栈大小：

```powershell
g++ main.cpp -Wl,--stack,268435456 -o main.exe
```

不改变时间复杂度，只提高进程栈上限。

### 1.2.008 无原生 `__int128` 时的双字 `i128`

编译器没有 `__int128`、但数值范围仍只需 $128$ 位时，用两个 `unsigned long long` 保存高低机器字比搬入任意精度整数更短。位型采用二进制补码：加减显式传递进位与借位，乘法把 $64$ 位数拆成两个 $32$ 位块求高半积，除法按位恢复商和余数。机器字必须是无符号型；若改成两个有符号整数，中间溢出会产生未定义行为。

```cpp
struct i128
{
    unsigned long long hi = 0; // 补码的高 64 位
    unsigned long long lo = 0; // 补码的低 64 位

    i128(int64_t x = 0) : hi(x < 0 ? ~0ULL : 0), lo((unsigned long long)x)
    {
        // 把 64 位有符号整数按补码符号扩展到 128 位
    }

    explicit operator bool() const
    {
        // 返回当前 128 位整数是否非零
        return hi || lo;
    }

private:
    i128(unsigned long long h, unsigned long long l) : hi(h), lo(l)
    {
        // h、l 是已经计算好的高、低 64 位补码
    }

    static bool lessU(i128 a, i128 b)
    {
        // 把 a、b 当作无符号 128 位整数，返回 a 是否小于 b
        return a.hi != b.hi ? a.hi < b.hi : a.lo < b.lo;
    }

    static unsigned long long mulHi(unsigned long long a, unsigned long long b)
    {
        // 返回 64 位无符号乘积的高 64 位
        constexpr unsigned long long MASK = 0xffffffffULL;
        unsigned long long a0 = a & MASK;
        unsigned long long a1 = a >> 32;
        unsigned long long b0 = b & MASK;
        unsigned long long b1 = b >> 32;
        unsigned long long p = a0 * b0;
        unsigned long long x = a0 * b1;
        unsigned long long y = a1 * b0;
        unsigned long long mid = (p >> 32) + (x & MASK) + (y & MASK);
        return a1 * b1 + (x >> 32) + (y >> 32) + (mid >> 32);
    }

public:
    friend i128 operator-(i128 x)
    {
        // 返回 x 的 128 位补码相反数
        auto lo = ~x.lo + 1;
        return i128(~x.hi + (lo == 0), lo);
    }

    friend i128 operator+(i128 a, i128 b)
    {
        // 返回 a+b 的低 128 位，低位溢出时向高位进位
        auto lo = a.lo + b.lo;
        return i128(a.hi + b.hi + (lo < a.lo), lo);
    }

    friend i128 operator-(i128 a, i128 b)
    {
        // 返回 a-b 的低 128 位，低位借位计入高位
        auto lo = a.lo - b.lo;
        return i128(a.hi - b.hi - (a.lo < b.lo), lo);
    }

    friend i128 operator*(i128 a, i128 b)
    {
        // 返回 a*b 的低 128 位
        return i128(mulHi(a.lo, b.lo) + a.hi * b.lo + a.lo * b.hi,
                    a.lo * b.lo);
    }

private:
    static pair<i128, i128> divU(i128 n, i128 d)
    {
        // n、d 按无符号解释且 d 非零；返回商与余数
        i128 q;
        i128 r;
        for (int i = 127; i >= 0; i--)
        {
            auto carry = r.hi >> 63;
            auto bit = i < 64 ? n.lo >> i & 1ULL : n.hi >> (i - 64) & 1ULL;
            r = i128(r.hi << 1 | r.lo >> 63, r.lo << 1 | bit);
            if (carry || !lessU(r, d))
            {
                r = r - d;
                if (i < 64)
                {
                    q.lo |= 1ULL << i;
                }
                else
                {
                    q.hi |= 1ULL << (i - 64);
                }
            }
        }
        return {q, r};
    }

    static pair<i128, i128> divS(i128 a, i128 b)
    {
        // b 非零且商可表示；返回向零取整的商和与 a 同号的余数
        auto na = a.hi >> 63;
        auto nb = b.hi >> 63;
        auto [q, r] = divU(na ? -a : a, nb ? -b : b);
        if (na != nb)
        {
            q = -q;
        }
        if (na)
        {
            r = -r;
        }
        return {q, r};
    }

public:
    friend i128 operator/(i128 a, i128 b)
    {
        // 返回 a/b 向零取整的商
        return divS(a, b).first;
    }

    friend i128 operator%(i128 a, i128 b)
    {
        // 返回 a%b，非零余数与 a 同号
        return divS(a, b).second;
    }

    string toString() const
    {
        // 返回当前值的十进制表示
        auto neg = hi >> 63;
        i128 x = neg ? -*this : *this;
        string s;
        do
        {
            auto [q, r] = divU(x, i128(10));
            s.push_back(char('0' + r.lo));
            x = q;
        } while (x);
        if (neg)
        {
            s.push_back('-');
        }
        reverse(s.begin(), s.end());
        return s;
    }

    friend ostream &operator<<(ostream &out, const i128 &x)
    {
        // 把 x 的十进制表示写入 out，并返回 out
        return out << x.toString();
    }
};
```

用 `i128 x = (int64_t)v` 从 $64$ 位整数构造，`cout << x` 直接输出。加、减、乘保留补码乘积的低 $128$ 位；若按有符号整数使用，应保证数学结果落在 $[-2^{127},2^{127}-1]$。除数必须非零，且不能计算结果无法表示的 $\frac{-2^{127}}{-1}$；商向零取整，余数与被除数同号。加减乘为 $O(1)$，除法固定做 $128$ 轮，转十进制为 $O(128d)$（$d\le 39$），额外空间均为 $O(1)$。编译器支持原生类型时优先用 [1.2.002 `__int128` 输入输出](#12002)；范围超过 $128$ 位时改用 [14.1.001 高精度整数（BigInt）](14-其他实用模板.md#141001)。

下面用一组负数运算和一个跨机器字的数检查五则运算、符号规则与除法：

```cpp
signed main()
{
    i128 x(-123456789), y(12345);
    assert((x + y).toString() == "-123444444");
    assert((x - y).toString() == "-123469134");
    assert((x * y).toString() == "-1524074060205");
    assert((x / y).toString() == "-10000");
    assert((x % y).toString() == "-6789");

    i128 cross;
    cross.hi = 1;
    cross.lo = 1;
    assert((cross / i128((1LL << 32) + 1)).toString() == "4294967295");
    assert((cross % i128((1LL << 32) + 1)).toString() == "2");
}
```

### 1.3.001 编译参数与调试构建

CLion 中为同一个 CMake 项目建立 `Release` 和 `Debug` 两个 Profile。Release 用于本地性能和提交前测试，Debug 用于定位越界、未定义行为和 STL 迭代器错误。下面的缓存变量应填入 CLion 的 CMake options；命令行构建时另加对应的 `-DCMAKE_BUILD_TYPE`。

最小 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.20)
project(acm)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(main main.cpp)
```

Release Profile 的 CMake options：

```text
-DCMAKE_CXX_FLAGS_RELEASE="-g -O2" -DCMAKE_EXE_LINKER_FLAGS_RELEASE="-static"
```

Debug Profile 的 CMake options：

```text
-DCMAKE_CXX_FLAGS_DEBUG="-O0 -g3 -gdwarf-4 -Wall -Wextra -Wshadow -Wconversion -Wsign-conversion -Wformat=2 -Warray-bounds=2 -Wstringop-overflow=4 -Wnull-dereference -Wduplicated-cond -Wlogical-op -Wvla -Wstack-usage=1048576 -Werror=return-type -fsanitize=undefined,bounds-strict -fsanitize-undefined-trap-on-error -fno-omit-frame-pointer -fno-optimize-sibling-calls -fstack-protector-all -DLOCAL -D_GLIBCXX_DEBUG -D_GLIBCXX_DEBUG_PEDANTIC -D_GLIBCXX_ASSERTIONS" -DCMAKE_EXE_LINKER_FLAGS_DEBUG="-static"
```

参数作用如下：`-DCMAKE_CXX_FLAGS_RELEASE` 和 `-DCMAKE_CXX_FLAGS_DEBUG` 分别设置两种构建的 C++ 编译参数；`-DCMAKE_EXE_LINKER_FLAGS_RELEASE` 和 `-DCMAKE_EXE_LINKER_FLAGS_DEBUG` 分别设置可执行文件的链接参数。`-g` 保留 Release 调试信息，`-O2` 开启常用安全优化；`-O0` 关闭优化便于单步，`-g3` 生成包含宏的完整调试信息，`-gdwarf-4` 使用 DWARF v4。

`-Wall` 开启常见警告，`-Wextra` 开启额外警告，`-Wshadow` 检查变量遮蔽，`-Wconversion` 检查可能改变数值的隐式转换，`-Wsign-conversion` 检查有符号和无符号转换，`-Wformat=2` 加强 `printf` / `scanf` 格式检查，`-Warray-bounds=2` 加强数组越界分析，`-Wstringop-overflow=4` 加强字符串和内存写入越界分析，`-Wnull-dereference` 检查可证明的空指针解引用，`-Wduplicated-cond` 检查重复条件，`-Wlogical-op` 检查可疑逻辑运算，`-Wvla` 警告运行时长度数组，`-Wstack-usage=1048576` 在函数栈使用量可能超过 $1$ MiB 时警告，`-Werror=return-type` 把缺失返回值等返回类型错误视为编译错误。

`-fsanitize=undefined` 检查常见未定义行为，`-fsanitize=bounds-strict` 加强边界检查，`-fsanitize-undefined-trap-on-error` 在发现 UBSan 错误后直接触发 trap；需要可读的诊断文本时可以暂时删掉最后一项。`-fno-omit-frame-pointer` 保留帧指针，`-fno-optimize-sibling-calls` 禁止尾调用优化，二者便于回溯；`-fstack-protector-all` 为函数增加栈破坏保护。`-DLOCAL` 开启本地代码，`-D_GLIBCXX_DEBUG` 开启 libstdc++ 调试迭代器，`-D_GLIBCXX_DEBUG_PEDANTIC` 开启更严格的 STL 检查，`-D_GLIBCXX_ASSERTIONS` 开启标准库断言。`-static` 要求静态链接可执行文件，缺少对应静态库时会链接失败；`_GLIBCXX_DEBUG` 改变 STL ABI，Debug 和 Release 对象不能混合链接。

临时不用 CLion 时，可在 PowerShell 用下面的精简命令；完整告警、STL 检查和静态链接仍以上面的两个 Profile 为准。

```powershell
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow main.cpp -o main.exe
g++ -std=c++20 -O0 -g3 -gdwarf-4 -Wall -Wextra -Wshadow '-fsanitize=undefined,bounds-strict' -fsanitize-undefined-trap-on-error -fno-omit-frame-pointer -fno-optimize-sibling-calls -DLOCAL main.cpp -o main_debug.exe
```

下面是 GCC 优化选项清单。它是卡常查询表，不是默认提交前导；必须先用普通 `-O2` 版本和固定输入确认瓶颈，再逐项打开并对拍。`#pragma GCC optimize` 只影响其后的函数或翻译单元，`#pragma GCC target` 还会改变生成的指令集。

```cpp
#if defined(__GNUC__)
#pragma GCC optimize("O3,unroll-loops") // O3 增强优化；展开循环，减少循环控制开销。
#if defined(__x86_64__) || defined(__i386__)
#pragma GCC target("avx2,bmi,bmi2,lzcnt,popcnt,fma") // 开启下文逐项说明的六组 x86 指令。
#pragma GCC target("avx", "sse2") // 再开启 AVX 与 SSE2；x86-64 上 SSE2 通常已默认支持。
#endif
#pragma GCC optimize("Ofast") // 在 O3 上放宽浮点语义，可能破坏严格 IEEE 结果。
#pragma GCC optimize("inline") // 鼓励内联函数，减少调用开销。
#pragma GCC optimize("unroll-loops") // 展开循环，可能增大代码体积。
#pragma GCC optimize("-fgcse") // 消除全局公共子表达式。
#pragma GCC optimize("-fgcse-lm") // 加强循环中的加载移动和公共子表达式消除。
#pragma GCC optimize("-fipa-sra") // 跨函数拆分聚合参数，减少无用字段传递。
#pragma GCC optimize("-ftree-pre") // 对树形中间表示做部分冗余消除。
#pragma GCC optimize("-ftree-vrp") // 传播变量取值范围，删除不可能分支。
#pragma GCC optimize("-fpeephole2") // 执行目标相关的局部指令改写。
#pragma GCC optimize("-ffast-math") // 允许不严格 IEEE 规则的浮点优化。
#pragma GCC optimize("-fsched-spec") // 允许更激进地提前调度指令。
#pragma GCC optimize("-falign-jumps") // 对齐跳转目标，可能改善取指。
#pragma GCC optimize("-falign-loops") // 对齐循环入口。
#pragma GCC optimize("-falign-labels") // 对齐普通代码标签。
#pragma GCC optimize("-fdevirtualize") // 将可确定目标的虚调用改为直接调用。
#pragma GCC optimize("-fcaller-saves") // 在调用附近保存寄存器，减少溢出到内存。
#pragma GCC optimize("-fcrossjumping") // 合并不同分支末尾的相同代码。
#pragma GCC optimize("-fthread-jumps") // 重排条件跳转，减少连续跳转。
#pragma GCC optimize("-funroll-loops") // 再次显式指定循环展开。
#pragma GCC optimize("-freorder-blocks") // 重排基本块，让常走路径顺序执行。
#pragma GCC optimize("-fschedule-insns") // 在寄存器分配前调度指令。
#pragma GCC optimize("inline-functions") // 鼓励普通函数内联。
#pragma GCC optimize("-ftree-tail-merge") // 合并不同分支的相同尾部。
#pragma GCC optimize("-fschedule-insns2") // 在寄存器分配后再次调度指令。
#pragma GCC optimize("-fstrict-aliasing") // 假设不同类型指针不别名；违反规则会出错。
#pragma GCC optimize("-falign-functions") // 对齐函数入口。
#pragma GCC optimize("-fcse-follow-jumps") // 沿条件跳转路径继续消除公共子表达式。
#pragma GCC optimize("-fsched-interblock") // 允许跨基本块调度指令。
#pragma GCC optimize("-fpartial-inlining") // 只内联函数中实际需要的部分。
#pragma GCC optimize("no-stack-protector") // 关闭栈保护，只适合确认安全的性能实验。
#pragma GCC optimize("-freorder-functions") // 重排函数布局，改善代码局部性。
#pragma GCC optimize("-findirect-inlining") // 间接目标可确定时尝试内联。
#pragma GCC optimize("-fhoist-adjacent-loads") // 提前条件两侧相邻的加载操作。
#pragma GCC optimize("-frerun-cse-after-loop") // 循环优化后再次消除公共子表达式。
#pragma GCC optimize("inline-small-functions") // 鼓励内联小函数。
#pragma GCC optimize("-finline-small-functions") // 与上一项同类，鼓励内联小函数。
#pragma GCC optimize("-ftree-switch-conversion") // 将部分 switch 转为查表或位判断。
#pragma GCC optimize("-foptimize-sibling-calls") // 做尾调用优化，减少栈使用。
#pragma GCC optimize("-fexpensive-optimizations") // 开启耗时但可能有效的优化。
#pragma GCC optimize("inline-functions-called-once") // 内联只调用一次的函数。
#pragma GCC optimize("-fdelete-null-pointer-checks") // 按未定义行为假设删除无效空指针检查。

// -fstrict-overflow：基于没有有符号溢出的假设优化。
// -fcse-skip-blocks：旧版 CSE 跳块选项。
// -funsafe-loop-optimizations：基于循环满足额外约束优化。
#endif
```

目标参数中，`avx2` 把多数整数 SIMD 扩展到 256 位，`bmi` 提供 `andn`、`blsi` 等基础位操作，`bmi2` 提供 `pext`、`pdep` 等扩展位操作，`lzcnt` 提供前导零计数，`popcnt` 提供置位计数，`fma` 提供单次舍入的融合乘加，`avx` 提供 256 位浮点 SIMD，`sse2` 提供 128 位整数与双精度浮点 SIMD。这些指令只能在评测机明确支持时开启，否则程序可能直接收到非法指令；本机可用 `-march=native` 让 GCC 按当前 CPU 选择，但不能据此假定评测机也支持。

选项边界必须记住：`-O3` 通常已经包含大多数普通 `-f*` 优化，重复列出不等于再次加速；`-Ofast` 与 `-ffast-math` 允许破坏严格 IEEE 浮点语义；`-fstrict-aliasing` 依赖程序遵守别名规则；`no-stack-protector` 会降低栈保护；展开、对齐、内联和调度可能增大代码并使指令缓存变差。`#pragma once` 只是头文件保护，与性能无关。

这些参数只影响常数，不改变渐进复杂度。`-fsanitize` 用于调试，不能与面向提交的极限优化混用；Linux 提栈用 [1.2.007](#12007) 的 `ulimit`，MinGW 才使用 `-Wl,--stack,字节数`。卡常前先用 [1.5.001 卡常使用边界与专题索引](#15001) 的基准步骤确认瓶颈。

```bash
testcase() {

}
```

### 1.3.004 checker

对拍时区分严格文本、忽略行尾空格、浮点误差三类比较。浮点比较同时给绝对和相对容差，任一满足即视作相等，避免大数只看相对、小数只看绝对时的误判。

```cpp
bool equalFloat(long double x, long double y,
                long double absErr = 1E-9L,
                long double relErr = 1E-9L)
{
    // 绝对或相对误差任一达标即视为相等
    if (isnan(x) || isnan(y))
    {
        return false;
    }
    if (isinf(x) || isinf(y))
    {
        return x == y;
    }
    auto d = abs(x - y);
    return d <= absErr || d <= relErr * max(abs(x), abs(y));
}
```

整数与构造题不能擅用浮点 checker；输出任意合法解的题应校验约束本身，而非与标准输出逐字比较。比较 $n$ 个 token 为 $O(n)$。

### 1.3.005 对拍器（Windows / Linux）

对拍 = 生成器反复造随机数据，喂给待测程序和一个信得过的参考程序，比对结果，首个反例立即停并保留那组输入。生成器种子取自命令行参数（`gen 1`、`gen 2`……），同一种子永远产生同一组数据，反例可复现。按判定方式分两类：**逐字比对**（答案唯一）与 **special judge**（答案多解，用 checker 程序判）。

固定命名：`gen` 生成数据，`my` 是待测程序，`brute` 是可信的暴力或参考程序。生成器从 `argv[1]` 读取种子。下面脚本只在失败时输出 `WA on i`，反例保存在 `in.txt`。

常规题用 `fc /b` 或 `diff -q` 严格比较；按空白分隔 token 或允许浮点误差时，改用题目对应的 checker。`dp.bat`：

```bat
@echo off
for %%x in (gen my brute) do (g++ -std=c++20 -O2 %%x.cpp -o %%x.exe || exit /b)
set i=0
:loop
set /a i+=1
gen.exe %i% > in.txt
my.exe < in.txt > my.out
brute.exe < in.txt > bf.out
fc /b my.out bf.out > nul
if not errorlevel 1 goto loop
echo WA on %i%
```

`dp.sh`：

```bash
#!/bin/bash
for x in gen my brute; do g++ -std=c++20 -O2 "$x.cpp" -o "$x" || exit; done
for ((i=1;;i++)); do
    ./gen "$i" > in.txt
    ./my < in.txt > my.out
    ./brute < in.txt > bf.out
    diff -q my.out bf.out > /dev/null || { echo "WA on $i"; break; }
done
```

SPJ 题有多组合法输出，checker 直接验证待测输出，退出码 `0` 表示 AC。下面示例检查输出正整数 $x,y$ 且 $x+y=n$；比赛时只替换中间的题目约束：

```cpp
#include <bits/stdc++.h>
using namespace std;
signed main(signed argc, char *argv[])
{
    if (argc != 3) return 1;
    ifstream in(argv[1]), out(argv[2]);
    int n, x, y;
    if (!(in >> n) || !(out >> x >> y)) return 1;
    out >> ws;
    return !(x > 0 && y > 0 && x + y == n && out.eof());
}
```

Linux / WSL 的 `itr.sh`：

```bash
#!/bin/bash
for x in gen my interactor; do g++ -std=c++20 -O2 "$x.cpp" -o "$x" || exit; done
for ((i=1;;i++)); do
    ./gen "$i" > in.txt
    python3 interact.py ./my ./interactor in.txt || { echo "WA on $i"; break; }
done
```

交互器从隐藏数据文件读取测试并在答错时返回非零；解答和交互器每次输出后都必须刷新。直接运行 `itr.bat` 或 `bash itr.sh`，通过时静默，失败时只输出种子。单轮耗时为本轮所有进程之和，脚本不负责时限。

### 1.3.006 随机数据生成器

生成可复现随机数据，覆盖边界（最小、最大、重复、有序）与随机情形。种子取自 `argv`，同一种子永远产生同一组数据。绝不用 `rand()`——它的低位周期短、分布差。

```cpp
signed main(signed argc, char **argv)
{
    // 种子来自命令行第一个参数，缺省为 1
    auto seed = argc > 1 ? stoull(argv[1]) : 1ULL;
    mt19937_64 rng(seed);
    int n = uniform_int_distribution<int>(1, 50)(rng);
    cout << n << '\n';
    for (int i = 0; i < n; i++)
    {
        cout << uniform_int_distribution<int>(-100, 100)(rng)
             << " \n"[i + 1 == n];
    }
}
```

图数据生成后要额外检查连通、无重边等题目约束。生成 $n$ 个元素为 $O(n)$。

### 1.3.007 GNU C++ 环境、本地计时与评测机测速

先输出标准版本、编译器版本、指针位数和优化状态；`__cplusplus >= 202002L` 才能依赖 C++20。实际程序耗时用 `steady_clock` 包住 `solve()`，只在 `LOCAL` 下输出到 `cerr`。

```cpp
cout << __cplusplus << '\n';
cout << __VERSION__ << '\n';
cout << sizeof(void *) * 8 << '\n';
#ifdef __OPTIMIZE__
cout << "optimized\n";
#endif

#ifdef LOCAL
auto beg = chrono::steady_clock::now();
#endif
solve();
#ifdef LOCAL
auto end = chrono::steady_clock::now();
cerr << chrono::duration<double, milli>(end - beg).count() << " ms\n";
#endif
```

热身赛比较本机与评测机速度时，使用固定的 `mt19937` 工作块。每块生成 $10^7$ 个随机数并滚动异或；`speedCheck` 是该固定过程的真实结果。轮数和块数各做一次 `volatile` 读取，循环内部仍是普通局部变量；返回值必须进入最终输出或错误分支，因此 `-O2` 不能把整段计算当作无用代码删除。

```cpp
volatile int speedRounds = 10000000; // 每块生成次数；修改后必须重算 speedCheck
volatile int speedBlocks = 1;        // 重复块数；测速时只调整这一项
constexpr uint32_t speedCheck = 3894306128U;

#if defined(__GNUC__)
__attribute__((noinline))
#endif
uint32_t speedBlock()
{
    // 返回固定随机序列的滚动异或摘要
    int n = speedRounds;
    mt19937 rng(712367821);
    uint32_t h = 0;
    for (int i = 0; i < n; i++)
    {
        h = rotl(h, 7) ^ rng();
    }
    return h;
}

uint32_t speedTest()
{
    // 重复 speedBlocks 块；全部摘要正确时返回 0
    int k = speedBlocks;
    uint32_t bad = 0;
    for (int i = 0; i < k; i++)
    {
        bad |= speedBlock() ^ speedCheck;
    }
    return bad;
}
```

本地计时调用如下；`bad` 必须打印或判断，不能只测一个未使用的返回值。

```cpp
auto beg = chrono::steady_clock::now();
uint32_t bad = speedTest();
auto end = chrono::steady_clock::now();
cerr << chrono::duration<double, milli>(end - beg).count()
     << " ms, check = " << bad << '\n';
```

评测机测速先令 `speedBlocks=0` 提交一次，记基线时间为 $t_0$；再令 `speedBlocks=k` 提交，记时间为 $t_k$。以下时间均换算为秒。一个块约耗时 $(t_k-t_0)/k$，该评测机每秒约执行

$$
\frac{10^7k}{t_k-t_0}
$$

次本测试循环，一秒对应的块数约为 $k/(t_k-t_0)$。时间显示较粗时取 $k=8$ 或 $16$，直到 $t_k>t_0$；只返回 AC/TLE 时，提交一个只运行 `speedTest()` 并输出检查值的程序，按 $1,2,4,8,\ldots$ 增大块数，首次 TLE 后在最后两个值间二分。若时限是 $L$ 秒、边界附近可通过 $k$ 块，则一秒约能运行 $k/L$ 块，即约 $10^7k/L$ 次本测试循环；该值受时间取整和机器负载影响，只取近似。整数答案可写 `ans ^= speedTest()`，正确时异或零而不改变答案；字符串或多行输出在正式输出前写 `if (speedTest()) return 1;`。测速通常只调整 `speedBlocks`；修改 `speedRounds` 后必须本地输出一次 `speedBlock()`，用新摘要替换 `speedCheck`。测速只代表当前编译器下的 `mt19937` 和整数运算速度，不能替代图、内存、I/O 或具体算法的最坏数据测试。环境信息为 $O(1)$；测速为 $O(\textit{speedRounds}\cdot\textit{speedBlocks})$ 时间和 $O(1)$ 额外空间。

使用上述固定工作块实测时，各平台每秒完成的块数约为：

| 平台 | 每秒块数 | 每秒本测试循环次数 |
| --- | ---: | ---: |
| Codeforces | $42$ | $4.2\times 10^8$ |
| QOJ | $51$ | $5.1\times 10^8$ |
| 洛谷 | $47$ | $4.7\times 10^8$ |
| 牛客 | $30\sim 31$ | $3.0\times 10^8\sim 3.1\times 10^8$ |
| AtCoder | $72$ | $7.2\times 10^8$ |
| PTA | $27$ | $2.7\times 10^8$ |

本次实测未记录具体评测机型号、编译器版本与重复轮数，以上数据只用于赛前粗略估算，不能视为平台的固定性能。

### 1.3.008 调试输出与断言

`debug(x)` 只在本地定义 `LOCAL` 时打印到 `cerr`，提交时展开为空语句，不影响 `cout` 结果。`assert` 内不要放有副作用的语句——`-DNDEBUG` 会整体删除表达式，副作用随之消失。

```cpp
#ifdef LOCAL
#define debug(x) cerr << #x << " = " << (x) << '\n'
#else
#define debug(x) ((void)0)
#endif

assert(0 <= l && l <= r && r <= n);
```

关闭时 $O(1)$，开启时取决于输出量。

### 1.3.009 常见未定义行为和易错点清单

提交前快速排查“本地能跑、评测漂移”的问题：

- 有符号整数溢出是未定义行为；只有乘积可能超出当前类型时，才对该表达式局部转成 `__int128`，普通加减优先用边界比较改写。
- 不对负数或超位宽做位移；`1ULL << k` 要求 $0\le k<64$。
- 不解引用 `end()`，不在容器扩容后沿用旧迭代器、指针或引用。
- `sort` 比较器必须严格弱序，不能写成 $a\le b$（自反会崩溃或死循环）。
- 不同时使用关闭同步的 iostream 与 stdio。
- 递归深度、数组下标、空容器 `back()`、除零、负数取模都要单独检查。

只在 `-O2` 下出错时，第一步跑 ASan/UBSan（[1.3.001](#13001)），不要先加 `volatile` 或关优化掩盖问题。清单本身无运行时复杂度。

## 1.4 STL、扩展库与防卡

### 1.4.001 `vector`、`array`、`string`、`tuple`、`pair`

`vector` 管运行时动态连续空间，`array` 管编译期定长，`string` 管字节串，`pair/tuple` 管小型聚合。已知最终长度用 `resize` 一次到位，只知上界用 `reserve` 预留避免反复搬迁。

```cpp
vector<int> a(n);
array<int, 4> d{1, 0, -1, 0};    // 常用于四方向偏移
pair<int, int> e{x, y};
auto [u, v] = e;                 // 结构化绑定
```

`string` 下标按字节，不按 Unicode 字符。随机访问 $O(1)$，`push_back` 摊还 $O(1)$，中间插删 $O(n)$。

### 1.4.002 `stack`、`queue`、`deque`、`priority_queue`

分别对应后进先出、先进先出、双端、堆。`priority_queue` 默认大根堆，小根堆传 `greater<>`；它不支持删除任意元素，需要动态删除时用延迟删除双堆或带删堆（[3.5.009](#35009)）。

```cpp
priority_queue<int> mx;                              // 大根堆
priority_queue<int, vector<int>, greater<>> mn;      // 小根堆
deque<int> q;
```

需要遍历全部元素时直接用底层 `vector/deque`。栈、队列、双端两端操作 $O(1)$；堆插入、弹出 $O(\log n)$，取顶 $O(1)$。

### 1.4.003 `set`、`multiset`、`map`、`multimap`

需要有序键、前驱后继或稳定最坏复杂度时用红黑树容器。`multiset::erase(x)` 按值删除全部等于 `x` 的元素；只删一个时先用 `find` 精确查找，再删除该迭代器。

```cpp
multiset<int> s;
auto it = s.find(x);
if (it != s.end())
{
    s.erase(it);
}
```

不要用 `distance(s.begin(), it)` 求排名——它对树迭代器是 $O(n)$；要排名用 PBDS 有序树（[1.4.006](#14006)）。查找、插删均 $O(\log n)$。

### 1.4.004 `unordered_map` / `unordered_set` 防 hack 哈希

标准哈希对整数近乎恒等，出题人能构造大量同桶键把它卡成 $O(n)$ 每次。用 SplitMix64 充分扰动、再混入进程启动时间做随机种子，构造者无法预测桶分布。

```cpp
struct CustomHash
{
    static uint64_t mix(uint64_t x)
    {
        // SplitMix64 finalizer：雪崩扰动
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }

    size_t operator()(uint64_t x) const
    {
        // 混入随机种子，抵御针对固定哈希的构造
        static const uint64_t seed =
            (uint64_t)chrono::steady_clock::now().time_since_epoch().count();
        return mix(x + seed);
    }

    size_t operator()(const pair<int, int> &x) const
    {
        // 只接受两个整数分量的 pair
        static const uint64_t seed =
            (uint64_t)chrono::steady_clock::now().time_since_epoch().count();
        uint64_t a = mix((uint64_t)x.first + seed);
        uint64_t b = mix((uint64_t)x.second + seed + 0x9e3779b97f4a7c15ULL);
        return mix(a ^ rotl(b, 32));
    }
};
```

```cpp
unordered_map<int, int, CustomHash> cnt;
cnt.reserve(n * 2);          // 预留减少重哈希
cnt.max_load_factor(.7);
```

单个整数键和由两个整数组成的 `pair` 可以直接使用该哈希；字符串或复合键应另写与键类型对应的哈希器。操作期望为 $O(1)$，最坏仍为 $O(n)$；要求稳定最坏复杂度时改用 `map`。

### 1.4.005 `bitset` 与手写 bitset

编译期定长首选 `bitset<N>`；长度运行时才定用 `DynamicBitset`——按 $64$ 位机器字打包，位运算天然 $\tfrac1{64}$ 加速。下面这份提供置位、清空、查询、计数、按位与/或，够覆盖“布尔可达性并行转移”一类用途；需要移位再按题补充，避免做成难核对的完整容器。

```cpp
struct DynamicBitset
{
    int n = 0;                    // 有效位数
    vector<unsigned long long> a; // 按 64 位机器字打包

    DynamicBitset(int m = 0)
    {
        // 构造 m 位的全零集合，要求 m>=0
        init(m);
    }

    void init(int m)
    {
        // 把集合重设为 m 位并清零
        assert(m >= 0); // 调试检查，可删
        n = m;
        a.assign((n + 63) / 64, 0);
    }

    void set(int p, bool v = true)
    {
        // 第 p 位写成 v
        assert(0 <= p && p < n); // 调试检查，可删
        auto b = 1ULL << (p & 63);
        if (v)
        {
            a[p >> 6] |= b;
        }
        else
        {
            a[p >> 6] &= ~b;
        }
    }

    void reset()
    {
        // 全部有效位清零
        fill(a.begin(), a.end(), 0);
    }

    bool test(int p) const
    {
        // 返回第 p 位
        assert(0 <= p && p < n); // 调试检查，可删
        return a[p >> 6] >> (p & 63) & 1ULL;
    }

    int count() const
    {
        // 1 的总数
        int ans = 0;
        for (auto x : a)
        {
            ans += popcount(x);
        }
        return ans;
    }

    DynamicBitset &operator|=(const DynamicBitset &o)
    {
        // 逐位或入 o，返回当前集合
        assert(n == o.n); // 调试检查，可删
        for (int i = 0; i < (int)a.size(); i++)
        {
            a[i] |= o.a[i];
        }
        return *this;
    }

    DynamicBitset &operator&=(const DynamicBitset &o)
    {
        // 逐位与入 o，返回当前集合
        assert(n == o.n); // 调试检查，可删
        for (int i = 0; i < (int)a.size(); i++)
        {
            a[i] &= o.a[i];
        }
        return *this;
    }
};
```

`init(m)` 要求 $m\ge0$，单点接口要求 $0\le p<n$，两个集合做按位运算时位数必须相同。单点操作为 $O(1)$，计数与按位运算为 $O\!\left(\frac{n}{64}\right)$。以下固定例覆盖机器字边界 $63/64$、末位、清位与按位或：

```cpp
signed main()
{
    DynamicBitset a(70);
    a.set(0);
    a.set(63);
    a.set(69);
    DynamicBitset b(70);
    b.set(64);
    a |= b;
    assert(a.count() == 4 && a.test(63) && a.test(64));
    a.set(69, false);
    assert(a.count() == 3 && !a.test(69));
    a.reset();
    assert(a.count() == 0);
}
```

### 1.4.006 GNU PBDS

PBDS 是 libstdc++ 的非标准扩展，只能在提供相应头文件的 GNU 环境中使用。常用接口包括支持排名的 `tree`、可改键与合并的 `priority_queue`，以及 `cc_hash_table`、`gp_hash_table`。哈希表的默认哈希仍然可预测；需要抵御构造碰撞时，应显式使用 [1.4.004](#14004) 的随机化哈希器。下面给出四类接口的最小调用方式：

```cpp
#include <ext/pb_ds/assoc_container.hpp>
#include <ext/pb_ds/priority_queue.hpp>
#include <ext/pb_ds/tree_policy.hpp>

using namespace __gnu_pbds;

template <class T> using OrderedSet = tree<
    T, null_type, less<T>, rb_tree_tag,
    tree_order_statistics_node_update>;

using MinHeap = __gnu_pbds::priority_queue<
    int, greater<int>, pairing_heap_tag>;

using ResizePolicy = hash_standard_resize_policy<
    hash_exponential_size_policy<>,
    hash_load_check_resize_trigger<>,
    true>;

using SizedHashMap = gp_hash_table<
    unsigned long long, // 64 位无符号键，保留完整机器字范围
    int,
    CustomHash,
    equal_to<unsigned long long>,
    direct_mask_range_hashing<>,
    linear_probe_fn<>,
    ResizePolicy>;

void pbdsExample(int x, int id, int k)
{
    OrderedSet<pair<int, int>> s;
    s.insert({x, id});
    auto rank = s.order_of_key({x, numeric_limits<int>::min()});
    assert(0 <= k && k < (int)s.size()); // 调试检查，可删
    auto value = *s.find_by_order(k);

    MinHeap a;
    MinHeap b;
    auto it = a.push(5);
    a.modify(it, 2);
    a.erase(it);
    a.join(b);

    cc_hash_table<int, int, CustomHash> chain;
    gp_hash_table<int, int, CustomHash> probe;
    chain[x]++;
    probe[x]++;

    SizedHashMap mp1;
    mp1.resize(1ULL << 20); // 批量插入前把桶数调到 2 的幂
    mp1[(unsigned long long)x]++;
    cout << rank << ' ' << value.first << '\n';
}
```

有序树的插入、删除、排名和第 $k$ 小为 $O(\log n)$；解引用 `find_by_order(k)` 前要求 $0\le k<\lvert s\rvert$，比较器必须是严格弱序，不能用 `less_equal` 模拟多重集合。`pairing_heap_tag` 的 `modify` 按摊还 $O(\log n)$ 使用，`join` 为 $O(1)$；哈希表操作只有期望 $O(1)$。

`gp_hash_table::resize` 只有在 `hash_standard_resize_policy` 的第三个模板参数 `External_Size_Access` 为 `true` 时才能从外部调用；默认策略取 `false`，直接调用会编译失败。它接收扩容策略的表容量目标，不等同于按元素数预留的 `unordered_map::reserve`，也不保证能容纳同样数量的元素而不再扩容。这里的 `direct_mask_range_hashing` 用掩码定位桶，容量应取 $2$ 的幂；`resize` 会重散列已有元素，故应在批量插入前调用。`CustomHash` 仍负责抵御构造碰撞。具体策略与兼容性见 [3.9 PBDS 专题](03-数据结构.md#39)。

### 1.4.007 `lower_bound`、`upper_bound`、`unique`、`iota`

二分有序区间、去重、生成连续编号。`unique` 只把重复项移到尾部并返回新逻辑末尾，必须配 `erase` 才真正删除。二分前必须满足对应有序/单调条件。

```cpp
sort(a.begin(), a.end());
a.erase(unique(a.begin(), a.end()), a.end());               // 排序去重
auto l = lower_bound(a.begin(), a.end(), x) - a.begin();    // 首个 >= x
auto r = upper_bound(a.begin(), a.end(), x) - a.begin();    // 首个 > x
iota(id.begin(), id.end(), 0);                              // 0,1,2,...
```

随机访问迭代器二分 $O(\log n)$；`unique`、`iota` 为 $O(n)$。

### 1.4.008 `next_permutation`、`prev_permutation`、`shuffle`

按字典序枚举排列或随机打乱。从排序后的序列起循环 `next_permutation`，可无重复地枚举多重集合的全部排列。`random_shuffle` 已被移除，一律用 `shuffle` 配 `mt19937`。

```cpp
sort(a.begin(), a.end());
do
{
    use(a);
} while (next_permutation(a.begin(), a.end()));

shuffle(a.begin(), a.end(), rng);
```

每次排列推进 $O(n)$，枚举 $P$ 个排列共 $O(Pn)$；打乱 $O(n)$。

### 1.4.009 `accumulate`、`is_sorted`、迭代器

求和、验有序、写泛型区间代码。累加初值决定结果类型：`#define int long long` 改不了字面量 `0` 的 `int` 类型，大整数求和仍须显式写 `0LL`，否则中途溢出。

```cpp
auto sum = accumulate(a.begin(), a.end(), 0LL);   // 初值 0LL 定死 long long
assert(is_sorted(a.begin(), a.end()));
for (auto it = a.begin(); it != a.end(); it++)
{
    use(*it);
}
```

均为 $O(n)$ 时间、$O(1)$ 额外空间。

### 1.4.010 `__builtin_*` 与 C++20 位运算函数

统计位数、找最高位、二进制上取整。C++20 的 `popcount/bit_width/bit_ceil/countr_zero` 要求无符号实参，比 `__builtin_*` 更安全：`countr_zero(0)` 有定义（返回位宽），而 `__builtin_ctzll(0)` 未定义。

```cpp
auto u = (unsigned long long)x;
auto ones = popcount(u);                                  // 1 的个数
int hi = u ? (int)bit_width(u) - 1 : -1;                 // 0 的最高位约定为 -1
auto p2 = bit_ceil((unsigned long long)max<int>(1, n));   // >= n 的最小 2 的幂
auto z = countr_zero(u);                                  // 末尾 0 的个数
```

这些操作通常编译为单条或少量指令，视为 $O(1)$。调用 `bit_ceil` 时还要保证结果能由实参的无符号类型表示。

### 1.4.011 sort killer 与哈希 hack

理解旧式快排和固定哈希会被构造数据卡退化，据此做防御（非鼓励攻击评测）：

1. 排序直接用标准库 `sort`——它是 introsort，最坏退化时自动转堆排序，保证 $O(n\log n)$ 次比较。
2. 哈希表用 `CustomHash`、`reserve` 与较低装载因子（[1.4.004](#14004)）。
3. 需要稳定最坏复杂度时用 `map/set` 或排序离线处理。

哈希仍只有期望 $O(1)$。

### 1.4.012 何时才需要卡常

只在复杂度正确且剖析已经定位瓶颈后降低常数。卡常不能替代算法改进，具体入口见 [1.5.001 卡常使用边界与专题索引](#15001)。常规提交先检查以下事项：

- 连续数据优先 `vector` 并提前 `reserve`，避开链式容器与频繁分配。
- 热循环避免 `endl`（每次 flush）、虚函数、重复取模、`std::function` 类型擦除。
- 用 `bitset`/机器字并行处理布尔转移。
- 快读只在 I/O 确占主要时间时启用。
- 编译器、评测机指令集和内存限制必须满足所用优化的条件。

只改常数，不改渐进复杂度。

### 1.4.013 字符串分割：getline / Split

按单字符分隔符切分整行，并保留连续分隔符产生的空字段——这是它与 `stringstream` 按空白切分的关键区别：后者会吞掉空字段。

```cpp
vector<string> split(const string &s, char sep = ' ')
{
    // 按 sep 切分，保留空字段
    vector<string> ans;
    string cur;
    for (auto c : s)
    {
        if (c == sep)
        {
            ans.push_back(cur);
            cur.clear();
        }
        else
        {
            cur.push_back(c);
        }
    }
    ans.push_back(cur);
    return ans;
}
```

`split("a,,bc,", ',')` 得到 `{"a", "", "bc", ""}`。按任意空白切数字用 `stringstream`，按固定字符且空字段有意义时用 `split`。长度 $n$ 时 $O(n)$。

### 1.4.014 `optional`

`optional<T>` 表示“一个 `T` 或没有值”，适合表达查找失败、无解等状态，避免拿 `-1`、`INF` 等可能与合法答案冲突的哨兵。默认构造和 `nullopt` 都表示空；装入一个 `T` 后才可以解引用。

```cpp
optional<int> firstPos(const vector<int> &a, int x)
{
    // 返回 x 在 a 中首次出现的下标，不存在时返回空
    for (int i = 0; i < (int)a.size(); i++)
    {
        if (a[i] == x)
        {
            return i;
        }
    }
    return nullopt;
}

void optionalExample(const vector<int> &a, int x)
{
    // 输出 x 的首次出现位置，并演示置值与置空
    auto pos = firstPos(a, x);
    if (pos)
    {
        cout << *pos << '\n';
    }
    else
    {
        cout << "not found\n";
    }

    optional<int> ans;
    ans = 42;                  // 现在含有值 42
    ans.reset();               // 重新置空
    int v = ans.value_or(-1);  // 空时取得默认值 -1
    cout << v << '\n';
}
```

用 `if (x)` 或 `x.has_value()` 判空，确认非空后用 `*x`、`x->member` 访问；`value()` 在空值上会抛出 `bad_optional_access`，竞赛代码通常先判空。`value_or(defaultValue)` 只提供一个替代值，不会改变原对象；`optional` 只区分成功与无值，需要区分多种失败原因时改用状态码或 `variant`。除所存对象自身的构造、析构成本外，判空、访问、`reset` 均为 $O(1)$；设 `a` 的长度为 $n$，示例 `firstPos` 的时间复杂度为 $O(n)$、额外空间为 $O(1)$。

### 1.5.001 卡常使用边界与专题索引

普通提交先用 `-O2`、连续容器、预留容量和 [1.2.001 快速输入输出](#12001)。确实接近时限时再从 [1.3.001 编译参数与调试构建](#13001) 的 GCC 清单逐项试验，并对同一固定输入核对答案和时间。下表保留各类平台优化的有效结论；具体快慢依赖 CPU、编译器、数据分布和问题规模，不把一次本机结果写成普遍顺序。

| 技术 | 适用条件 | 复杂度与边界 |
|---|---|---|
| AVX2 自动向量化或专用循环 | x86 评测机明确支持 AVX2，数据连续且循环无依赖 | 扫描 $n$ 项仍为 $O(n)$ 时间、$O(1)$ 额外空间；一次处理更多元素只改变常数，不同 CPU 上收益可能反转 |
| PCLMUL / NEON PMULL | 固定宽度二进制多项式乘法，且运行平台支持对应指令 | 固定 $64$ 位硬件乘法视为 $O(1)$；标量回退需逐位处理，推广到 $w$ 位时为 $O(w^2)$，均为 $O(1)$ 额外空间 |
| 延迟约减 | 已证明一个分块内全部乘加不会超过累计类型 | 长度 $n$ 的点积为 $O(n)$ 时间、$O(1)$ 额外空间；块长必须由模数和累计类型上界推出，不能只靠经验值 |
| radix-4 NTT、根表复用与频域驻留 | 固定友好模数、长度满足单位根条件，并有大量同规模卷积 | [10.1.003 NTT](10-多项式、变换与线性递推.md#101003) 已给 `FastNTT`、radix-2 回退、固定校验和与本机基准；两版均为 $O(N\log N)$ 时间、$O(N)$ 空间，基准差异只作当前环境参考 |
| `mmap` / `fread` / 手写输出缓冲 | 输入确实占主要时间；`mmap` 还要求普通文件，管道输入必须回退 | 读写 $B$ 字节均为 $O(B)$；固定缓冲额外空间为 $O(S)$，映射额外占用 $O(B)$ 虚拟地址空间，是否更快依赖系统与输入来源 |
| arena / 空闲表 | 大量等生命周期小对象，析构可统一处理 | 预留 $C$ 字节后单次顺序分配为 $O(1)$，清空为 $O(1)$，占用 $O(C)$；需要逐对象析构或未知峰值时不适合 |
| CSR / SoA / 分块与预取 | 图或记录静态，遍历受缓存而非运算限制 | CSR 建表 $O(n+m)$ 时间和空间，完整扫描 $O(m)$；预取和字段拆分不改变复杂度，收益必须按目标平台实测 |
| 位表、分支提示与经验阈值 | 状态域固定且表可由算法定义生成 | 固定 $64$ 位 `popcount` 或查表视为 $O(1)$；阈值选择为 $O(1)$，被选择算法仍按自身复杂度计算，阈值须记录基准环境 |

固定模乘可选 [7.1.009 Barrett 约减](07-数论.md#71009) 或 [7.1.010 Montgomery 模乘](07-数论.md#71010)。AVX2、PCLMUL、`mmap`、通用内存池、手写预取和经验阈值没有一份能直接适用于所有题目的短接口，因此这里只保留选择条件与严格界；需要时在当前题目代码旁写专用版本和可移植回退。依赖具体测试答案的硬编码、越界访问和有符号溢出不属于优化。
