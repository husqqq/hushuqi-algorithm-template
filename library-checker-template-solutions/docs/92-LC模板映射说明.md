# Library Checker 与模板映射表

本表是按模板板块执行 LC 流程前的唯一入口。权威数据位于同目录的 `LC_TEMPLATE_MAPPING.tsv`：按 `chapter`、`template_item` 排序，每行一个 LC 唯一标识 `<category>/<problem>`，因此可直接筛选某一章节并得到该章节应处理的题目。`chapter` 是负责完成该题 LC 闭环的工作流章节，`template_item` 可以来自另一个章节的公共接口。一个模板条目可以有多行；每个 LC 题必须恰有一行。

收到章节编号时直接用 `rg "^NN\t" LC_TEMPLATE_MAPPING.tsv` 读取该章全部映射；不能从 manifest 或现有提交反推范围。有缺口时，`不可完全置信清单/chapter-NN.md` 是尚未取得映射审计、当前源码或任一当前正确性证据的派生视图，可用于安排处理顺序；零缺口时目录自动删除，权威题集始终是 TSV。

- 字段 `audited` 仅表示已有审计文档已经做过源码级映射；`classified` 仅表示本轮完成题意和现有条目归类，仍必须按受控流程逐题审阅、生成、验证和提交。映射表本身不改变任何题目的在线状态。

## 使用规则

1. 先运行 `python library-checker-template-solutions/tools/check_lc_template_mapping.py`；只有集合、重复和模板条目校验通过，才开始任何章节。
2. 处理第 `NN` 章时，在 TSV 取 `chapter=NN` 的全部行；不得用当前 `manifest.json` 或已存在题解缩小范围。
3. 每个 LC ID 只以 TSV 中的一个位置为主映射。跨章节依赖写进单题审计的依赖列，但不能复制主映射。
4. 发现无法映射的官方题时，先在对应章节审计保留 `template_gap`，完成模板修改、源码对照和测试后再写入 TSV；这一步必须先阅读编写规范。

映射关系只负责路由，正式的审阅、候选生成、本地验证和在线提交状态仍以各章 `*_AUDIT.md` 和 `manifest.json` 为准。
