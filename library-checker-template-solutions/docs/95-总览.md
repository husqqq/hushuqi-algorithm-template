# Library Checker 当前模板解答

按章节工作时，先在 `LC_TEMPLATE_MAPPING.tsv` 用两位章节号筛选，例如 `rg "^04\t" LC_TEMPLATE_MAPPING.tsv`；不要用 manifest 中已有候选缩小题集。当前冻结题集没有模板缺口，范围完全由 TSV 定义。运行 `python tools/refresh_untrusted_inventory.py` 会刷新 `不可完全置信清单/`，其中按章列出映射、当前源码或正确性证据仍有缺口的项目；本地验证或同哈希线上 AC 任一成立即可作为当前正确性证据，零缺口时目录自动删除。

这里专门保存准备由用户当前模板生成并验证的 Library Checker 提交源码，与恢复的参考目录 `../library-checker-solutions/` 并列。参考目录只用于研究算法与比较性能；不得把参考源码作为提交候选，也不得用参考代码的 AC 证明当前模板通过。

当前候选数量与分类必须直接读取 `manifest.json`，不得在文档硬编码；这个数只描述候选集合，不是官方分类覆盖证明。每题只保留：

```text
<category>/<problem>/main.cpp
<category>/<problem>/meta.json
```

每个 `main.cpp` 都是该题唯一、自包含的验证与提交候选，已经包含该题所需的模板实现和输入输出。它只能引用尖括号系统头，禁止引用本地 `.hpp` 或仓库内其他源码。验证器编译、提交器发送、服务端回显校验都直接使用这一个文件，不维护任何中间提交源码或历史源码副本。它是否确实来自当前模板不能只靠 `meta.json` 声明，必须先通过《模板复查与受控提交流程》的确定性生成证明或人工双复核来源门。

`manifest.json` 保存题目索引、当前源码 SHA256 和官方题库版本；每题 `meta.json` 保存来源说明和在线记录。第 03 章固定官方 commit 的 `data_structure/` 47 题均已有当前模板生成的独立源码。实际通过本地编译、模板测试及官方 sample/boundary/random checker 用例的题目，只能以当前默认收据的 `problems` 字段和自动生成的 `03-数据结构审计.md` 为准，不能由候选数推断。性能门、当前 `online_ac` 数量和逐题状态也由该审计实时记录；在 47 题都取得当前线上 AC 前仍不能称为该分类已全部提交。

某章在 manifest 中没有候选，只表示该章源码闭环尚未完成，不代表没有对应 LC 题。章节范围只从 `LC_TEMPLATE_MAPPING.tsv` 冻结；发现题目不能映射时，先按编写规范补模板、完成源码级审阅后再写入 TSV，从订正后的模板生成 `main.cpp` 和 `meta.json`、加入 manifest、本地验证并真实在线提交。完成这些闭环前，不能报告相应章节已经完成 LC 复查。

目录职责如下：

```text
<category>/<problem>/                 当前唯一自包含提交源码与逐题元数据
docs/                                 长期流程、映射、审计与工具说明；章节审计按模板章节编号
tools/                                可复用的生成、验证、提交和报告工具
  tests/                              工具回归测试
LC_TEMPLATE_MAPPING.tsv              按章节查找 LC 题的权威路由表
不可完全置信清单/                    有缺口时按章生成的状态报告；零缺口时不存在
.local/                                仅此处保存不入库的工具依赖与本地状态
  library-checker-problems/            固定 commit 的官方题库工作树
  yosupo-profile/                      Playwright 浏览器登录状态
  yosupo-local-verification.json       当前已验证题目的收据（覆盖范围以 problems 字段为准）
  ch03-performance/                    当前源码的性能门证据
  ch03-batches/                        当前源码的单题提交前批次
  ch03-pre-meta/                       单题提交前元数据快照
  ch03-results/                        单题最终线上结果
```

`.local/` 不保存题解源码，也不属于参考实现；工作区其他目录不再建立同名本地状态目录。已结束命令的日志、一次性登录辅助脚本和 Python 缓存不属于证据，应在确认无活进程后清理。

33 题的逐项算法、复杂度和参考实现对照见 [`10-多项式审计.md`](10-多项式审计.md)；第 03 章数据结构题的覆盖缺口、逐项映射、执行反思和线上结果见 [`03-数据结构审计.md`](03-数据结构审计.md)。

后续章节反向覆盖、模板订正、独立源码生成、清单登记、授权模式判定和在线调优必须遵循 [`90-模板复查与受控提交流程.md`](90-模板复查与受控提交流程.md)。

## 本地验证

在线提交前必须运行：

以下命令均从工作区根目录 `template/` 执行。

```text
python library-checker-template-solutions/tools/verify_local.py --all
```

验证器直接对本次选择的 manifest 候选执行 GNU++20 编译、模板测试、固定样例、边界和可复现随机测试，并把输出交给官方 checker 判定。成功后，收据写入被 Git 忽略的 `.local/yosupo-local-verification.json`，每题只绑定一个当前源码 SHA256、官方题库提交版本和测试结果；收据实际覆盖范围以其中的 `problems` 字段为准，不能从 manifest 总数推断。`--all` 不会发现尚未进入 manifest 的官方题；任何章节都必须先按流程文档核对“主责分类全集 + `93-其他分类审计.md` 分配题”的最终覆盖矩阵。

任一 `main.cpp`、清单、测试集合或官方题库版本变化后，旧收据立即失效。提交器会在认证前和发送前重新计算同一份 `main.cpp` 的 SHA256；缺少当前源码对应的完整通过记录时拒绝提交。

第 03 章的性能、批次和结果 JSON 必须由 Python 工具的 `--output` 直接以 UTF-8 无 BOM、LF 写入 `library-checker-template-solutions/.local/`。不要用 PowerShell 的 `>`、`Tee-Object` 或文本管道保存这些含中文模板路径的 JSON，否则控制台代码页可能改变规范化内容与 SHA256。

```powershell
python library-checker-template-solutions/tools/benchmark_ch03.py `
  --only <problem> --output .local/ch03-performance/<problem>.json

python library-checker-template-solutions/tools/ch03_batch_report.py `
  --only <problem> `
  --performance-file .local/ch03-performance/<problem>.json `
  --output .local/ch03-batches/<problem>.json

python library-checker-template-solutions/tools/submit_yosupo.py --submit `
  --only <problem> `
  --batch .local/ch03-batches/<problem>.json `
  --jobs 1
```

## 查看与提交

以下命令只列出当前题目和源码，不登录、不发送请求：

```text
python library-checker-template-solutions/tools/submit_yosupo.py --dry-run
python library-checker-template-solutions/tools/submit_yosupo.py --dry-run --only inv_of_formal_power_series
```

默认模式无需逐批征求用户同意。只有完成章节真实映射、参考实现驱动的模板订正、当前来源证明、哈希、收据、测试、官方 checker、性能、工具和题库版本门禁并生成报告后，题目才进入 `direct_authorized`，随后直接逐题提交。只有用户明确要求本章、本批或本题提交前确认时，才停在 `approval_pending` 等待当前批次 SHA256 的批准。脚本会原样发送该题目录中的 `main.cpp`：

```text
python library-checker-template-solutions/tools/submit_yosupo.py --submit --only inv_of_formal_power_series
```

一个章节可以连续推进多题，但每个提交批次和线上命令都只能包含一个题目；取得该题最终可认证 AC、写回元数据和覆盖矩阵并生成最终单题报告后，才能为下一题生成新批次。章节级审批要求也逐题批准各自 SHA256。禁止用多题 `--only` 或 `--all` 批量发送；出现非 AC、哈希异常、`submission_unknown` 或工具失败时立即停止，未知请求的重复提交仍须用户明确许可。

完整命令、安全限制和判定口径见 [`91-Yosupo自动提交指南.md`](91-Yosupo自动提交指南.md)。

账号、密码、Firebase ID Token、Cookie 和浏览器登录状态都不会写入仓库，也不得发送到聊天中。提交器优先无头复用固定 profile 中的有效登录态；只有登录态失效时，用户才在脚本打开的一个可见浏览器中手动登录。短期令牌只保存在脚本进程内存中。
